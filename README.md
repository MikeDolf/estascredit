# estascredit.ru — сайт СИНОТЕХ

Статический сайт на чистом HTML/CSS/JS, без сборки и зависимостей. Деплоится
через GitHub Pages на домен **estascredit.ru**.

## Структура репозитория

```
index.html                              — главная (лендинг)
articles/index.html                     — список статей
articles/<slug>.html                    — отдельные статьи
assets/css/style.css                    — общие стили для всех страниц
assets/js/main.js                       — общий JS (меню, FAQ-аккордеон, форма заявки)
CNAME                                   — домен для GitHub Pages
robots.txt, sitemap.xml                 — базовая SEO-разметка
```

Каждая HTML-страница самодостаточна: подключает `assets/css/style.css` и
`assets/js/main.js` по относительному пути и не требует сборки — можно
открыть файл прямо в браузере.

## Как добавить новую статью

1. Скопируйте любой файл из `articles/*.html` (например,
   `articles/kak-vybrat-ekskavator-iz-kitaya.html`) под новым именем —
   латиницей, через дефис, без пробелов (`slug.html`).
2. Замените `<title>`, `<meta name="description">`, `og:*` теги,
   содержимое `.breadcrumbs`, `.article-header` и `.article-body`.
3. Добавьте карточку новой статьи в `articles/index.html` (блок
   `.articles-grid`, скопируйте один `<a class="article-card">`).
4. Добавьте новый `<url>` в `sitemap.xml`.
5. Закоммитьте и запушьте — правки на GitHub Pages появляются через
   1–2 минуты после пуша в основную ветку.

Стили для текста статей уже готовы в `assets/css/style.css` (класс
`.article-body`): заголовки `h2`/`h3`, списки, цитаты `blockquote`,
таблицы — используйте обычную HTML-разметку внутри `.article-body`.

## Проверки перед коммитом

```
python3 _checks/check_site.py
```

Проверяет по всем собранным страницам: битые внутренние ссылки и якоря,
валидность JSON-LD, дубли `title`/`description`, `<img>` без `alt`,
опечатки (пропущенный пробел после запятой, повтор слова, непарные кавычки),
заглушки в публикации, запретные фразы-противоречия и совпадение
«один анкор → один URL» (защита от каннибализации запросов).

Возвращает код 1 при любом нарушении. Сейчас скрипт красный намеренно:
он держит в виду телефон-заглушку и TODO-метки, которые уйдут вместе с
реальными данными.

Списки `FORBIDDEN_PHRASES` (противоречия условиям работы) и
`ARITHMETIC_RULES` (проверка числовых утверждений) заполняются по фактуре
бизнеса — пока пустые.

## Что помечено как TODO

Контакты (телефон, email, адрес, ссылки на соцсети) и страницы политики
конфиденциальности/оферты сейчас — плейсхолдеры из шаблона. Ищите
комментарии `<!-- TODO: ... -->` в `index.html`, `articles/index.html` и
файлах статей и замените на реальные данные, когда они появятся.

## Настройка GitHub Pages (сделать один раз вручную)

Через API репозитория Pages включить нельзя, поэтому это единственный шаг,
который нужно сделать руками в интерфейсе GitHub:

1. Слить ветку с сайтом в `main` (или сделать `main` рабочей веткой).
2. **Settings → Pages**.
3. **Source**: Deploy from a branch.
4. **Branch**: `main`, папка `/ (root)` → **Save**.
5. В поле **Custom domain** появится `estascredit.ru` (подхватится из файла
   `CNAME`) — подтвердите и дождитесь проверки DNS.
6. Включите **Enforce HTTPS**, как только сертификат будет выпущен
   (обычно несколько минут после проверки DNS).

## Настройка DNS у регистратора домена estascredit.ru

Добавьте у регистратора домена такие записи:

**Вариант A — apex-домен (estascredit.ru):**

| Тип | Хост | Значение             |
|-----|------|-----------------------|
| A   | @    | 185.199.108.153        |
| A   | @    | 185.199.109.153        |
| A   | @    | 185.199.110.153        |
| A   | @    | 185.199.111.153        |

**Вариант B — если сайт нужен на www.estascredit.ru:**

| Тип   | Хост | Значение                  |
|-------|------|----------------------------|
| CNAME | www  | `<github-username>.github.io` |

(актуальный список IP-адресов GitHub Pages проверяйте в официальной
документации GitHub Pages, они могут обновляться).

DNS может обновляться до 24–48 часов, обычно быстрее.

## Генератор

```
python3 _build/build.py --pilot   # только пары с уникальным текстом
python3 _build/build.py           # вся сетка товар × город
```

Сетка: 7 товарных направлений × 35 городов = 245 страниц, сборка около
0,2 секунды. Данные лежат в `_build/data/`, шаблон — в `_build/templates/`.
В шаблоне нет ни одного предложения, зависящего от товара: иначе оно было бы
одинаковым на всех страницах сетки.

**Собирать всю сетку можно только после уникализации.** Страница без
уникального абзаца и трёх своих вопросов FAQ — это дубль, и тираж таких
страниц работает против сайта. Сборка печатает покрытие уникализацией при
каждом прогоне; `--pilot` собирает только готовые пары.

`sitemap.xml` генерируется из результата сборки и руками не правится.

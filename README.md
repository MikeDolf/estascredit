# estascredit.ru — УралФорклифт

Сервис подбора вилочных погрузчиков в Свердловской области. Статический
HTML на GitHub Pages, домен **estascredit.ru**.

> **Модель: подбор, а не продажа.** Техника не наша, склада нет, цену
> устанавливает поставщик, оплата идёт мимо нас. Вознаграждение платит
> поставщик, для покупателя подбор бесплатен. Это не деталь оформления:
> формулировки продавца («наш склад», «купить у нас», «в корзину») на сайте
> недопустимы — сборка проверяет их по списку `FORBIDDEN_WORDING` в
> `_build/data/site.py` и падает, если найдёт.
>
> Причина: самозанятость (НПД) запрещает и перепродажу товаров, и
> посредническую деятельность по агентским договорам. Законная схема здесь —
> договор возмездного оказания услуг по поиску клиентов, где исполнитель
> действует от своего имени, не подписывает сделок за стороны и не проводит
> через себя деньги. **Договор с поставщиком должен составить юрист.**

> **Страницы генерируются.** Не правьте `index.html` и другие собранные
> страницы руками — следующая сборка затрёт правку. Текст живёт в
> `_build/data/`, разметка — в `_build/build.py` и `_build/templates/`.

## Сборка

```
python3 _build/build.py        # собрать сайт
python3 _checks/check_site.py  # проверить перед коммитом
python3 _build/make_images.py  # пересобрать картинки (нужно редко)
```

У сборки и проверки зависимостей нет — только стандартная библиотека Python 3.
`make_images.py` дополнительно требует `cwebp` (`brew install webp libtiff`):
`sips` умеет читать WebP, но записывать его не умеет. Готовые `.webp` лежат
в репозитории, так что для обычной сборки cwebp не нужен.

Сборка печатает, чего не хватает для запуска, и какие страницы закрыты от
индексации. Проверка сейчас зелёная — держите её такой.

`check_site.py` проверяет требования из `on-page-seo.md`: длину `title`
(50–60) и `description` (150–160), наличие `og:image`, `twitter:*` и
`apple-touch-icon`, ровно один `<h1>`, отсутствие пропущенных уровней
заголовков. Плюс битые ссылки и якоря, дубли `title`/`description`,
невалидный JSON-LD, `<img>` без `alt`, опечатки и один анкор, ведущий на
разные URL. Длины — самая частая поломка: короткое название города или
лишнее слово выбивают описание из диапазона, и проверка это ловит.

## Структура

```
_build/build.py              сборщик: шапка, подвал, SEO-обвязка, sitemap, robots
_build/templates/base.html   оболочка страницы (<head>, шапка, подвал)
_build/data/site.py          реквизиты компании, меню, контакты
_build/data/catalog.py       категории и позиции каталога
_build/data/pages.py         сервисные и юридические страницы
_build/data/cities.py        гео-страницы по городам области
_build/photos/               оригиналы фотографий техники (в вёрстку не идут)
_build/make_images.py        оригиналы → assets/img/*.webp, обложка, иконка
_checks/check_site.py        статические проверки
_relay/worker.js             Cloudflare Worker: приём заявки, отправка в MAX
assets/css/style.css         стили (правятся руками, не генерируются)
assets/js/main.js            меню, фильтры, сортировка, форма заявки
```

Собираемые страницы: главная, три категории (`/catalog/...`), четыре страницы
доверия (о сервисе, как это работает, гарантия и сервис, контакты), две
юридические (политика конфиденциальности, условия оказания услуг), шесть
гео-страниц, список статей. Итого 17.

## Что сделано по SEO

Разобрано на исходном коде конкурента (advanta-ekb.ru) и внедрено:

- **JSON-LD граф** на каждой странице: `Organization`, `WebSite`, тип самой
  страницы (`WebPage`/`CollectionPage`), `BreadcrumbList`, а где есть
  вопросы — `FAQPage`
- **Хлебные крошки** на всех внутренних страницах, в разметке и визуально
- Canonical, Open Graph, Twitter Card, `theme-color` — из одного шаблона
- Отдельная страница на каждый тип двигателя со своим `title`/`h1`/описанием
- `sitemap.xml` и `robots.txt` генерируются, страницы с `noindex` в карту
  не попадают
- Слоты под коды Яндекс.Вебмастера, Search Console и счётчик Метрики —
  заполняются в `_build/data/site.py`, разметка появляется автоматически

Сознательно **не** сделано:

- Нет разметки `Product`/`Offer` и нет цен на страницах. Мы не продавец:
  назвать цену вправе только поставщик. Ориентир по бюджету лежит в
  `data-price` и работает на фильтр, но на экран не выводится.
- Разметка организации — `ProfessionalService` с `serviceType`, а не
  `Organization` с товарами. Это описание услуги, а не магазина.
- Нет полей «в наличии»: наличие подтверждает поставщик под конкретный
  запрос, обещать его на сайте нельзя.
- Гео-страницы без собственного текста собираются с `noindex` и не попадают
  в sitemap. Шесть страниц, отличающихся одним названием города, — это дубли,
  которые тянут сайт вниз. Заполните `unique` и `faq` в `cities.py` —
  `noindex` снимется сам.

Реквизиты заполнены: Копырин Михаил Евгеньевич, ИНН 665805617047, самозанятый,
620017, Екатеринбург, ул. Фронтовых Бригад, 18, координаты 56.880553 / 60.631404.

**Проверьте индекс.** Справочники дают для дома 18 по этой улице индекс
620091, а не 620017. Индекс стоит в реквизитах и в разметке `PostalAddress`.
Часы работы заданы в двух местах `site.py` — человекочитаемо (`opening_hours`)
и в формате schema.org (`opening_hours_schema`); меняете одно — правьте оба.

Отдельно: **политику конфиденциальности и условия оказания услуг должен
просмотреть юрист.** Политика написана по структуре 152-ФЗ и отдельно
раскрывает передачу заявки поставщику — без этого раскрытия передача данных
третьему лицу незаконна. Реквизитов оператора в ней пока нет.

Фотографии подключены: четыре снимка в `_build/photos/`, из них собираются
версии 800 и 1600 px в WebP (20–80 КБ) плюс обложка 1200×630 для соцсетей.
Каждый `<img>` идёт с `srcset`, `sizes`, `width`/`height` и ленивой загрузкой,
кроме первой карточки. Снимков четыре, а позиций шесть — газовый и дизельный
погрузчик внешне не отличаются, поэтому кадры повторяются между категориями.

На синем погрузчике видна надпись стороннего бренда. На карточке-образце это
терпимо, но для обложки соцсетей взят кадр без логотипов: обложка представляет
нас, а не чужую марку.

## Инструменты разработки

Сайту они не нужны — нужны только для пересборки картинок и для скилла дизайна.

```
brew install node          # для wrangler (приём заявок) и для impeccable
brew install webp libtiff  # cwebp: кодирование картинок в WebP
```

**Impeccable** — набор правил дизайна ([impeccable.style](https://impeccable.style)),
установлен в `.claude/` этого проекта. В git не попадает: из-за `.nojekyll`
GitHub Pages отдаёт наружу всё содержимое репозитория, и 4,9 МБ чужих файлов
оказались бы в выкладке сайта. Установка через `npx impeccable install` не
работает — их эндпоинт скачивания отдаёт битый архив. Рабочий путь:

```
git clone --depth 1 https://github.com/pbakaus/impeccable /tmp/impeccable
cd /tmp/impeccable && bun install && bun run build:skills
cp -R /tmp/impeccable/dist/claude-code/.claude <корень проекта>/
```

## Что отдаётся наружу

`.nojekyll` отключает Jekyll, поэтому GitHub Pages публикует репозиторий
целиком: `/_build/`, `/_checks/`, `/_relay/worker.js` и `/.gitignore`
открываются по прямой ссылке. Секретов там нет — токены воркера живут в
переменных окружения Cloudflare. Но оригиналы фотографий в `_build/photos/`
это лишние 6 МБ в каждой выкладке; если захочется убрать, понадобится
`_config.yml` с `exclude` вместо `.nojekyll` либо публикация через Actions.

## Публикация

Правки на GitHub Pages появляются через 1–2 минуты после пуша в `main`.

### Настройка GitHub Pages (один раз, руками)

1. **Settings → Pages**
2. **Source**: Deploy from a branch
3. **Branch**: `main`, папка `/ (root)` → **Save**
4. В поле **Custom domain** подхватится `estascredit.ru` из файла `CNAME` —
   подтвердите и дождитесь проверки DNS
5. Включите **Enforce HTTPS**, когда выпустится сертификат

## Форма заявки

Сайт статический, бэкенда нет. Заявка уходит через Cloudflare Worker
(`_relay/worker.js`) в мессенджер MAX. Пока `LEAD_ENDPOINT` в
`assets/js/main.js` пуст, форма честно пишет «не подключена» и предлагает
написать в мессенджер — показывать «заявка принята» и никуда её не отправить
значит потерять обращение.

Разворачивание воркера описано в комментарии в начале `_relay/worker.js`.
